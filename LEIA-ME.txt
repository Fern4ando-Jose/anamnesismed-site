[CORRIGIDO 2026-06-07] BUG: tela de aceitar termos pedindo toda hora
Causa provável: a tabela "profiles" no Supabase tem RLS ativado mas falta uma
política de UPDATE — o salvamento de termos_aceitos/tipo_usuario falha
silenciosamente (erro só aparecia no console), e a cada novo carregamento o
perfil ainda está com termos_aceitos=false, então o gate aparece de novo.
Correção: o JS agora verifica o resultado do salvamento e mostra erro no botão
em vez de seguir adiante silenciosamente. MAS é necessário rodar este SQL no
Supabase (SQL Editor) para permitir que o próprio usuário atualize seu perfil:

  CREATE POLICY "Usuarios podem atualizar o proprio perfil"
  ON profiles FOR UPDATE
  USING (auth.uid() = id)
  WITH CHECK (auth.uid() = id);

Sem essa política, o UPDATE é bloqueado pelo RLS e o aceite nunca é salvo.
