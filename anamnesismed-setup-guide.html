Setup Completo

GitHub → Vercel → Supabase · Passo a passo
1
GitHub — Repositório do projeto
10 min
1
Criar conta no GitHub
Acessa github.com → Sign up → email + senha → confirma o email.
2
Criar repositório
No GitHub: clica em + → New repository
Nome: anamnesismed-site
Visibilidade: Public (necessário para Vercel gratuito)
Marca: ✅ Add a README file → clica Create repository
3
Fazer upload dos arquivos HTML
No repositório criado: clica em Add file → Upload files
Arrasta os 4 arquivos de D:\Claude\AnamnesisMed-site\:
anamnesismed-landing.html · anamnesismed-auth.html · anamnesismed-dashboard.html · anamnesismed-app.html

Clica em Commit changes → Done!
💡 Renomeia anamnesismed-landing.html para index.html antes de subir — assim o Vercel abre ela por padrão
2
Vercel — Site no ar
5 min
1
Criar conta no Vercel
Acessa vercel.com → Sign Up → Continue with GitHub
Autoriza o acesso ao GitHub. Conta criada automaticamente.
2
Importar o repositório
No Vercel Dashboard: Add New → Project
Seleciona o repositório anamnesismed-site
Framework: Other (não é React nem Next.js)
Clica em Deploy
🚀 Em ~1 minuto o site estará em: anamnesismed-site.vercel.app
3
Apontar o domínio (opcional agora)
Vercel Dashboard → seu projeto → Settings → Domains
Adiciona: anamnesismed.com
Vercel mostra os registros DNS para configurar no Namecheap.
HTTPS é automático — Let's Encrypt gratuito.
⏳ Pode fazer isso depois — o site já funciona em *.vercel.app enquanto testa
3
Supabase — Auth + Banco de Dados
20 min
1
Criar conta e projeto
Acessa supabase.com → Start your project
Entra com GitHub → New Project
Nome: anamnesismed · Senha do banco: anota numa parte segura
Region: South America (São Paulo) ou US East
Aguarda ~2 min para o projeto ser criado.
2
Copiar as chaves de API
No projeto Supabase: Settings → API
Copia e guarda num arquivo de texto:
• Project URL → ex: https://xyzxyz.supabase.co
• anon public key → chave longa que começa com eyJ...
⚠️ A anon key é pública — pode estar no código frontend. NÃO use a service_role key no frontend.
3
Habilitar Magic Link
No Supabase: Authentication → Providers → Email
Deixa Enable Email Provider ✅ ativo
Desativa Confirm email (por agora, para facilitar testes)
O magic link já está habilitado por padrão — nenhuma configuração extra necessária.
4
Criar as tabelas no banco
No Supabase: SQL Editor → New query
Cola e executa o SQL abaixo:
-- Tabela de perfis de usuário CREATE TABLE profiles ( id UUID REFERENCES auth.users PRIMARY KEY, nome TEXT, sobrenome TEXT, email TEXT, universidade TEXT, ano_curso TEXT, idioma TEXT DEFAULT 'es', plano TEXT DEFAULT 'trial', trial_end TIMESTAMPTZ DEFAULT (now() + interval '30 days'), stripe_id TEXT, criado_em TIMESTAMPTZ DEFAULT now() ); -- Tabela de histórias clínicas CREATE TABLE historias_clinicas ( id UUID DEFAULT gen_random_uuid() PRIMARY KEY, user_id UUID REFERENCES auth.users NOT NULL, motivo TEXT, motivo_id TEXT, especialidade TEXT, dados JSONB, status TEXT DEFAULT 'rascunho', criado_em TIMESTAMPTZ DEFAULT now(), atualizado_em TIMESTAMPTZ DEFAULT now() ); -- Segurança: cada usuário só vê suas próprias HCs ALTER TABLE profiles ENABLE ROW LEVEL SECURITY; ALTER TABLE historias_clinicas ENABLE ROW LEVEL SECURITY; CREATE POLICY "usuario ve proprio perfil" ON profiles FOR ALL USING (id = auth.uid()); CREATE POLICY "usuario ve proprias HCs" ON historias_clinicas FOR ALL USING (user_id = auth.uid()); -- Criar perfil automaticamente ao cadastrar CREATE OR REPLACE FUNCTION criar_perfil_novo_usuario() RETURNS TRIGGER AS $$ BEGIN INSERT INTO profiles (id, email) VALUES (NEW.id, NEW.email); RETURN NEW; END; $$ LANGUAGE plpgsql SECURITY DEFINER; CREATE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE criar_perfil_novo_usuario();
✅ Clica em RUN — se não der erro, as tabelas foram criadas
4

5 min
1
Adicionar as chaves do Supabase ao Vercel
No Vercel: seu projeto → Settings → Environment Variables

Adiciona as duas variáveis:
SUPABASE_URL = https://xyzxyz.supabase.co
SUPABASE_ANON_KEY = eyJhbGci...

Marca: ✅ Production ✅ Preview ✅ Development
Clica Save e depois Redeploy
⚠️ Depois de adicionar variáveis é necessário fazer redeploy para elas serem aplicadas
